Capability-aware device inventory
---------------------------------
Setup Scanner 1.0.2 extends the v2.2 inventory with per-connection driver-domain
and capability evidence:
- physical connection presence is separated from RZVIRTUAL/RZCONTROL binding nodes
- driverStack = windows-inbox or razer-filter
- Razer-owned INF files are separated from Microsoft/Windows Inbox INF files
- per-connection capabilities record whether RZVIRTUAL, RZCONTROL, Razer-bound
  nodes and Upper-/LowerFilters are actually required
- connectionType includes an evidence source; marketing terms such as HyperSpeed
  are not used to guess the active connection path

Empirically verified PID roles from four controlled native Windows scans:
1. Dongle only / keyboard switch Wireless: PID 02C9 present, PID 02CC absent
2. Cable only / keyboard switch Wire: PID 02C9 absent, PID 02CC present
3. Dongle + cable / switch Wire: PID 02C9 present, PID 02CC present
4. Dongle + cable / switch Wireless: PID 02C9 present, PID 02CC absent

Result:
- PID 02C9 = BlackWidow HyperSpeed Wireless-Dongle path
- PID 02CC = BlackWidow wired USB path
- Viper V3 Pro PID 00C1 remained present throughout all four BlackWidow-state tests

The two verified PID-role constants live only in the Setup profile layer. The
Health Engine contains no BlackWidow/Viper PID/model allowlist.

Health Engine 1.4.1
-------------------
Fixes the false FAILED state observed with the first generic inventory:
- Gate 2 validates only Razer-owned rzdevu_*/rzcommonu.inf DriverStore packages
- Microsoft Inbox INF files are valid and no longer treated as missing Razer packages
- Gate 5 requires RZVIRTUAL/RZCONTROL/Razer-bound nodes only when the active
  connection profile says the Razer filter stack uses them
- Gate 6 requires Upper-/LowerFilters only when the active connection profile
  declares device-filter capability
- Windows-Inbox-HID paths are INFO / not applicable for Gate 5/6 stack-specific checks
- relevant Razer filter-stack paths continue to receive the full checks

Expected current-system behavior after a fresh schema-2 Setup scan:
- Viper V3 Pro PID 00C1: healthy Windows-Inbox-HID path; no false RzDev/binding/filter FAIL
- BlackWidow PID 02C9 or PID 02CC: full RzDev/RZVIRTUAL/RZCONTROL/filter checks when physically active
- inactive alternate BlackWidow path remains profile evidence and does not fail Live-PnP
