AppEngine evidence architecture
-------------------------------
The former `Tail 8000` behavior is not expanded to a larger arbitrary number.
Instead the evidence model is split by semantics:

PRIMARY
  Direct current Windows/Razer system evidence. This class determines module /
  installation gates.

RUNTIME
  Time-sensitive evidence from the bounded latest AppEngine log window. The
  log probe is explicitly named `runtime-tail-8000` and is used for observations
  such as `isPowerOn` and `missing ffi handler`.

SUPPORTING
  Correlative AppEngine module/install messages. Missing, stale, unparsable or
  version-divergent lines are INFO context and can never independently promote a
  gate to HINWEIS/UNKLAR/FEHLER.

Direct-source gate contracts:
- Gate 7: Chroma Registry directly decides the component-registration state.
- Gate 10: Razer Game Manager Service 3 directly decides service health.
- Gate 11: RzComDriver SystemDriver/PnP evidence plus uninstall registration
  directly decide driver installation health.

The same SUPPORTING exclusion is enforced generically in:
- Health Engine gate severity
- Health Engine raw diagnostic severity/counting
- Go gate inspection/display severity

The six AppEngine module observations remain available as INFO/supporting
technical evidence, so diagnostics are not discarded; they are simply weighted
correctly.
