v2.2.5 guided connection learning
---------------------------------
The normal Setup scan remains generic and PID-free. Product identity continues
to prefer root USB DEVPKEY_Device_BusReportedDeviceDesc and groups connections
with the same normalized current bus identity into one product.

Connection-role semantics are no longer learned from random HID topology or
incidental one-path/two-path snapshots. Passive sources
`topology-hid-collection-asymmetry` and `topology-transition-confirmed` are not
present in the active Setup Scanner 1.0.4.

The Setup UI adds a guided calibration assistant. For each inventoried product:
1. the user creates a wired state and runs a product-scoped targeted scan;
2. the user creates a wireless state and runs a second product-scoped scan;
3. either step may be skipped without declaring the transport unsupported.

The host snapshots the pre-step inventory and passes CalibrationMode,
CalibrationProductKey and BaselinePath to Setup Scanner 1.0.4. Successful
assignments are HIGH-confidence and use only these runtime evidence sources:
- user-guided-wired-transition
- user-guided-wired-reference
- user-guided-wireless-transition
- user-guided-wireless-reference

Ambiguous observations, missing target/baseline or contradictory explicit
current descriptor evidence fail closed. A failed guided run does not commit the
candidate inventory and does not stage new connection history.

Connection History schema 2
---------------------------
Persistent learning path:
  Setup/RazerConnectionHistory-v2.json

Schema 2 adds calibrated/calibratedAt metadata. Setup Scanner 1.0.4 can read the
v2.2.4 schema-1 file as migration input. Schema-1 passive topology/transition
roles are not trusted as calibrated ground truth. Historical semantic role reuse
requires explicit descriptor evidence or guided calibration and remains guarded
by matching productKey.
