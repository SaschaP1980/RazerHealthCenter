v2.3.0 live presence / device-change architecture
-----------------------------------------------
- Persisted presentAtScan is historical until a current-session live refresh succeeds.
- App startup with a valid inventory automatically runs the fast known-PID live probe.
- Known-PID refresh uses current PresentOnly PnP evidence and avoids Registry history,
  DriverStore and INF traversal.
- A present connection is published live only after current USB-root product identity
  verifies to the stored productKey.
- RegisterDeviceNotificationW subscribes the Win32 window to device-interface changes.
- WM_DEVICECHANGE arrival/removal/node-change events are debounced and only trigger
  re-verification; the event itself is never identity or role evidence.
- PnP event bursts can queue one follow-up refresh so an early transient probe cannot
  strand the UI on a settling state.
- Probe-level errors fail closed and do not publish false absence/presence.
- Acid Green is based on fresh verified live presence only.
- Old inventories without deviceClass can recover mouse/keyboard presentation from
  stored MI_00 / mouhid / kbdhid evidence without changing the persisted inventory.

v2.3.0 guided connection learning
---------------------------------
- Verbindungen einlernen reuses the fast live infrastructure.
- Each selected-product step captures a fast baseline and then waits for a Windows
  device-change event before running a target-product delta probe.
- The target probe can discover a currently present PID not yet stored in the inventory,
  but only after current root identity verifies to the selected productKey.
- Wired learning requires exactly one unambiguous newly appeared verified connection.
- Wireless learning excludes the already-known HIGH wired connection and requires
  exactly one remaining verified target connection.
- Unrelated device events are ignored.
- Ambiguous delta, weak/missing identity and explicit descriptor-role conflicts fail
  closed and do not write Connection History.
- Successful roles remain HIGH with user-guided-wired-transition /
  user-guided-wireless-transition.
- Passive topology/HID asymmetry and incidental everyday transitions remain disabled
  as role-producing semantics.
- One normal full Setup scan after a successful guided sequence materializes complete
  capability/inventory metadata; interactive steps themselves stay on the fast path.
