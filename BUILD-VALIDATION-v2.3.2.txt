v2.3.2 UI / presentation scope
------------------------------
- A running known-PID live refresh immediately marks the previous presence state
  stale. The connection text remains visible but muted until the probe succeeds.
- Each product row overlays an indeterminate Acid-Green progress bar inside the
  VERBINDUNGS-PIDs cell while the fast live refresh is running.
- After successful live verification, both PID and learned role label are Acid
  Green; inactive known connections remain neutral/muted.
- Gate 4 normal findings enrich physical-node presentation with Setup product
  name, learned connection role and current verified alternative connection.
- Gate 4 raw details and clipboard-copy evidence remain the original Health
  Engine structured evidence unchanged; gate severity semantics are unchanged.
- Normal and raw gate-detail documents include 52 px bottom scroll reserve so the
  last line remains readable above the fixed Rohdetails/Kopieren button row.
- The PROTOKOLLE range header retains its 1-10-von-N counter but removes the
  redundant "Mausrad zum Scrollen" suffix; scroll behavior is unchanged.

Live / guided architecture
--------------------------
Unchanged from v2.3.1:
- persisted presentAtScan is historical until a current-session live refresh succeeds
- startup with a valid inventory automatically runs the known-PID PresentOnly probe
- known-PID live refresh avoids Registry history, DriverStore and INF traversal
- current USB-root product identity must verify to stored productKey before presence
  publication
- RegisterDeviceNotificationW / WM_DEVICECHANGE events only trigger debounced
  re-verification and are never identity/role evidence
- probe-level errors fail closed
- guided learning uses product-specific baseline -> event -> target delta probe
- ambiguity, weak identity or descriptor-role conflict writes no role/history
