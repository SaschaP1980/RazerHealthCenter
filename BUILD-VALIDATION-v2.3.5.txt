v2.3.5 live-presence performance optimization
--------------------------------------------
- The production live-presence hot path no longer launches powershell.exe.
- Startup and WM_DEVICECHANGE refreshes use native SetupAPI from Go.
- SetupDiGetClassDevsW is restricted to currently present devices of the USB
  enumerator; physical Razer USB roots are identified from their current
  instance IDs.
- Known-connection mode processes only PIDs already stored in the Setup
  inventory; unrelated roots are skipped before property retrieval.
- Current product identity is re-verified with
  DEVPKEY_Device_BusReportedDeviceDesc before a PID becomes live.
- Guided Wired/Wireless baseline and delta checks use the same native target-
  product probe and can still discover a previously unknown current PID.
- The former live PowerShell probe is no longer an active runtime payload and is
  retained only in docs/setup-history for provenance.
- PnP event bursts use a generation-based 800 ms quiet-window debounce before
  a probe starts. Repeated pending events replace the pending generation; only
  an event arriving while the short native probe is actually executing may
  retain one follow-up refresh.
- Diagnostics record implementation, requested PID set, verified present PID
  set, changed PID transitions, enumerated USB-node count, matched Razer-root
  count and native probe duration.
