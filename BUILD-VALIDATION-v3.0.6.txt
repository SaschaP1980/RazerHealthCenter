Razer Synapse + Chroma Health Center v3.0.6 - Final Build Validation
======================================================================

Scope
-----
v3.0.6 fixes the registry-view bug in the v3.0.5 product-registration guard
and integrates the first catalogued AppEngine user-mode recovery derived from
the real Windows failure/recovery investigation of 16 September 2026.

Registry-view correction
------------------------
- The official Razer manifest current_version_registry_key/value mapping is
  evaluated explicitly against Windows Registry64 and Registry32.
- A readable value in either view is PRESENT; the resolved view is persisted.
- No hard-coded WOW6432Node insertion is used.
- Version differences remain informational only and do not affect Health.

AppEngine user-mode health / recovery
-------------------------------------
- New read-only diagnostic: RHC.DIAG.APPENGINE.USERMODE 1.0.0.
- Gate 1 can become UNKNOWN / PRÜFUNG UNVOLLSTÄNDIG when the versioned
  AppEngine user-mode runtime is missing or incomplete even if some
  RazerAppEngine.exe process exists.
- Known problem: RHC.APPENGINE.USERMODE.RUNTIME_INCOMPLETE.
- New repair: RHC.REPAIR.APPENGINE.CONTROLLED_RUNTIME_RECOVERY 1.0.0.
- Explicit in-app confirmation is mandatory before mutation.
- The AppEngine recovery does not request automatic elevation.
- START_ONLY_RECOVERY starts only the existing validated Synapse+Chroma launch
  contract when no AppEngine process is active.
- FULL_RUNTIME_RESTART is allowed only with a unique signed versioned runtime
  and main process, and only the validated AppEngine runtime scope is stopped.
- No services, drivers, registry values, installed packages, or Razer files /
  configuration are modified by the recipe.
- Repair exit code 0 is insufficient; a separate read-only AppEngine
  diagnostic must verify runtime + Synapse + Chroma + systray.
- Existing Chroma service repair remains confirmation-required and UAC-based.

Native acceptance status
------------------------

validated on the affected Windows system and restored tray, volume wheel,
programmed key mappings, and Chroma. The integrated v3.0.6 build itself has not
yet been natively accepted. Registry32 handling in the integrated Go build and
the integrated FULL_RUNTIME_RESTART path still require native Windows acceptance.
