# RHC-43 — Active reusable interim Release contract (English, owner decision 2026-10-09)

**Publication is the terminal criterion for requested full-cycle work.** A Hotfix Work/Candidate is only *qualified source* until the official repo-downloads ZIP, source tag, release history, latest pointer, matching main model.go/CHANGELOG and independent remote readback are all proven. A blocked or unimplemented downstream step is a recorded release failure/incomplete result, not a reason to claim overall success.

The owner directs that the historical one-release v3.0.8.1 interim implementation be generalized to a bounded, repeatable **interim unsigned/uncertified** mode, beginning with v3.0.8.2. This is a new implementation task owned by [RHC-43](https://github.com/SaschaP1980/RazerHealthCenter/issues/43); do not confuse authorization to implement with evidence that the reusable pipeline has been implemented or qualified. The old v3.0.8.1 workflow/tag/archive are preserved as historical source, are now manual-dispatch-only and must not be recycled to publish any newer version.

## Required reusable-mode transaction

1. Resolve current main SHA, source appVersion/referenceVersion, CHANGELOG heading, public latest/releases history, every existing version tag, open Work/Candidate/Release refs and PRs. Demand a strictly newer four-part version than public latest; reject duplicate, downgrade, conflicting tag, stale branch, foreign PR or unknown write. Preserve every previously published ZIP byte-for-byte.
2. Qualify the exact approved source SHA using the selected Fast-/Work-Path, including Work BOOTSTRAP and Development Completion when Work is expressly requested. A source version-only Work PR may merge to main **before** release only when it has independently passed mandatory native Windows/Linux CI and source identity; then freeze the true **new main** SHA for the four-file Release PR. The ordinary production six-path Release transaction remains a separate mode. Never point a new tag to the historical Candidate by coincidence.
3. Before changing any public files, establish **two independent byte-identical Windows GUI PE builds and two identical seven-file Portable ZIPs**, correct PE/app version, actual ZIP file hashes, SHA-bound production source, tested manifest and immutable catalog append. Native hosted Windows PowerShell 5.1 must separately validate PS parsing, Go tests, repair-safety, and actual NotSigned state. Hosted Linux cross-compilation is not native Razer device testing.
4. In the explicitly approved interim mode record actual real safety results plus Phase B fields **DEFERRED/NOT_VERIFIED** (hardware, rollback, publisher signature/trust, SmartScreen owner acceptance and administrative ruleset enforcement). Do not change the existing production policy false/unknown/false and do not bypass user-confirmed Razer repairs, UAC/PID ambiguity guards or false-GREEN protection. The public README must disclose the unsigned executable, unverified publisher and SmartScreen risk.
5. Stage one new immutable Portable ZIP and **exactly four publication paths** (versioned ZIP, downloads/README.md, releases.json and latest.json) from a pinned qualified source main SHA in a one-parent release branch/PR. Enforce old history hashes, strict new version order, exact source/ZIP hash and unchanged branch/main before writes. Obtain separate trusted Linux/native Windows and downloads-integrity GitHub checks pinned to the staged SHA; auto-generated GitHub Actions PR/dispatch permissions must be observed, not assumed.
6. After successful trusted exact-SHA checks, merge the one true release PR, create or verify a unique immutable source tag at the actual frozen source SHA, and independently reread the real remote main SHA, two-parent merge, package Git blob/ZIP bytes/hash/size, runtime version, catalog history/latest, tag source identity and old releases. Verify or explicitly report postmerge cleanup by lease; no silent retries after ambiguous writes.
7. Only when the remote outcome is real may the Issue comment and user-facing summary claim **RELEASE VERIFIED**. Otherwise report **BLOCKED / NEEDS_ATTENTION** with exact source SHA, failed gates, GitHub run/job links and recovery action. Do not mistake a green Candidate or TEST-UNSIGNED QA artifact for distribution.

## Source-version/PR-gate compatibility rule — RHC-20 technical finalization

The published seven-file Portable ZIP is **not** the six-path Release-PR diff.
