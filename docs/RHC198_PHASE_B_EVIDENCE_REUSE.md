# RHC-198 Phase B — Qualified Candidate PE reuse (nonpublishing)

[Responsible Issue #198](https://github.com/SaschaP1980/RazerHealthCenter/issues/198); parent [RHC-190](https://github.com/SaschaP1980/RazerHealthCenter/issues/190).

**Optimization:** Avoid rebuilding the same Windows Portable EXE twice inside the Linux Publisher after Candidate already independently produced and compared two byte-identical Windows PE binaries. **No change to required actual hosted native Windows tests**, public RHC-102 or release hard gates.

## Exact immutable producer (Candidate Preflight)

Linux Candidate on the exact eligible `candidate/vVERSION` source:
1. Run full original Candidate/Issue/safety Python contracts.
2. Build *two independent* real Windows EXEs on Linux; byte-compare and SHA-256 both.
3. Independently produce and compare both Source ZIPs and both Portable ZIPs for deterministic source packaging.
4. Emit a real PE artifact `RHC190-CANDIDATE-PE-<source SHA>` with source/tree SHA, four-part version, repo, Candidate run ID and attempt, exact PE SHA-256, byte count, and a schema marker.
5. Upload immutable GitHub Actions artifact **before** marking the Linux Candidate job success. Both actual native Windows Candidate and aggregate Candidate qualification remain unchanged, and the Publisher is dispatched only by qualified Candidate.

## Exact consumer (Publisher Linux)

The Publisher independently checks original source SHA, main ancestry, version, policies, tests and immutable public release history. It resolves a **unique completed-success** Candidate Preflight run by exact SHA and version branch with a bounded wait, retrieves actual full run and job API metadata and downloads only the artifact attached to that run. `tools/rhc190_candidate_artifact.py verify` rejects:
- wrong source/tree SHA, version, repository, run ID or run attempt;
- wrong event, workflow path/name, foreign repo, wrong Candidate branch, wrong status or conclusion;
- **zero**, missing, duplicated, paginated, failed, skipped or incomplete hosted jobs; it requires exactly three real completed-success jobs named Candidate Linux / Candidate native Windows / Candidate qualification;
- missing/symlink/bad PE header, altered SHA-256, size mismatch or false deterministic build flags.

One source/mixed-run metadata shortcut never qualifies. The Publisher builds **two distinct byte-identical lean seven-file release ZIPs** from this independently attested Candidate PE. Publisher evidence records `candidatePeReused` and `candidatePeRunId`; its `twoIndependentPeBuilds=true` describes the two authentic **Candidate** builds, not fresh Publisher builds. ZIP catalog staging still requires the original complete proof, one combined source+downloads PR, prior immutable history, remote hash/tag and rollback-safe branch cleanup. No silent fallback to unchecked PE or synthetic pass.

## Independent security and release gates deliberately unchanged

Publisher on actual `windows-2025` continues PS5.1 script parsing, `go test ./...`, `go vet ./...`, Razer diagnostic/recovery/repair-safety checks, independently hashes extracted Linux-origin PE and ZIP bytes and verifies `Get-AuthenticodeSignature` state `NotSigned`. Candidate Windows already independently performed native tests. Public RHC-102 independently downloads the **real** published ZIP via HTTPS on Linux, rechecks Git graph and validates executable/repair safeguards on fresh hosted Windows, requiring all 3 actual jobs successful. All legacy production/signing/rollback policy fields remain blocked/unknown, physical hardware never inferred.

## Evidence and honest limitations

RED source checkpoint and GREEN hosted Work/PR qualification are recorded in Issue #198. No product version, download ZIP/catalog, immutable tag or public release is generated by this CI-only implementation. **Live Candidate→Publisher cross-workflow artifact retrieval and latency improvement are not verified until a later separately owner-authorized product release**; code/negative tests alone cannot prove live artifact availability, GitHub Action token scope or absolute speedup. If a hosted artifact retrieval or real run evidence cannot be independently verified, the future release must fail closed rather than silently compile elsewhere or skip native Windows tests. RHC-190 Phases C/D and multi-sample benchmarking remain outstanding.
